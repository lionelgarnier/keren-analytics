Quick Start

Get Easy Analytics running locally in mock mode (sample data, no Azure required).

1
Install dependencies 
npm install
2
Start the server 
npm run dev
3
Open the dashboard

Navigate to http://localhost:3000. Click Connect Azure (auto-connects in mock mode) or See live preview to view sample data without login.

Docker Deploy

Deploy with a single command using Docker Compose.

docker compose up --build

For Render.com, the repository includes a render.yaml blueprint. Click New > Blueprint in the Render dashboard and point to your repo.

Tip: The free Render tier sleeps after 15 minutes of inactivity. First load takes ~30s for cold start.

Azure Setup (Real Mode)

To connect real Azure telemetry, you need an Entra ID (Azure AD) app registration.

Prerequisites

  • Reader role on the Azure subscription
  • Log Analytics Reader on the workspace
  • App Insights must be workspace-based (not classic)

Quick start with CLI token

export AZURE_MODE=real
export AZURE_ACCESS_TOKEN="$(az account get-access-token \
  --resource=https://management.azure.com \
  --query accessToken -o tsv)"
npm run dev

Browser SSO (recommended)

Register an Entra ID app and configure environment variables:

AZURE_MODE=real
AZURE_CLIENT_ID=your-client-id
AZURE_CLIENT_SECRET=your-secret
AZURE_REDIRECT_URI=http://localhost:3000/auth/callback
SESSION_SECRET=random-secure-string
Security: Never commit secrets to git. Use .env files or your platform's secret management.

Campaigns & URL Parameters

Auto-detects UTM and custom URL parameters from your telemetry. No configuration needed — if your URLs contain ?utm_source=google, Easy Analytics finds it automatically.

How it works

  1. Every page view URL is scanned for query parameters
  2. Standard UTM parameters (utm_source, utm_medium, utm_campaign) get special treatment
  3. Custom parameters (ref, promo, ab_test) are also detected
  4. Pin any parameter to make it a permanent dashboard element

A/B Test Monitor

Automatically detects A/B tests from URL parameters and compares variant performance side-by-side. Add ?ab_test=variant_name to your URLs — Easy Analytics does the rest.

Zero config: No test setup required. Just add the URL parameter to your experiment URLs and the dashboard auto-detects and compares variants.

Session Timelines

Reconstructed user journeys from telemetry events. No screen recording needed — Easy Analytics builds a timeline from page views, clicks, conversions, and errors.

Each session shows: pages visited (with time on page), click events, conversion events, errors, and exit points.

API Reference

All endpoints return JSON. Authentication is handled via session cookies (set by the login flow).

Authentication

GET /auth/login

Initiates the login flow. In mock mode, auto-redirects. In real mode, redirects to Microsoft Entra ID.

GET /auth/session

Returns current session status.

{
  "authenticated": true,
  "tenantId": "mock-tenant",
  "mode": "mock",
  "oauthConfigured": false,
  "user": null
}
POST /auth/logout

Destroys the current session.

Dashboard

GET /dashboard/overview?range=7d

Returns the complete dashboard data including KPIs, charts, readiness score, and all visualizations.

range Time range: today, 7d (default), 30d
GET /azure/discover

Discovers App Insights resources in the connected Azure tenant.

POST /azure/select

Selects an App Insights resource for dashboard queries.

// Request body
{
  "resourceId": "/subscriptions/.../components/myapp",
  "workspaceId": "/subscriptions/.../workspaces/mylaw"
}

Prompts & Recommendations

GET /prompts

Returns LLM-ready prompts for each missing telemetry signal. Prompts are contextualized with the detected stack and resource name.

GET /recommendations

Returns improvement recommendations with readiness score.

Preview

GET /preview/dashboard?range=7d

Returns dashboard data with sample mock data. No authentication required. Useful for demos and testing.

Architecture

Easy Analytics is a lightweight Node.js service with a static frontend that orchestrates a deterministic pipeline.

src/
  server.js              # Express API server
  config.js              # Environment configuration
  core/
    orchestrator.js      # Pipeline state machine
    dashboard.js         # Dashboard query builder
    mapping.js           # Field mapping (userId, sessionId, pagePath)
    readiness.js         # Readiness probe analysis
    readinessScore.js    # Gamified 0-100 score
    promptGenerator.js   # LLM prompt generation
    cache.js             # In-memory cache with TTL
  azure/
    client.js            # Provider factory
    realClient.js        # Real Azure ARM + Log Analytics client
    mockClient.js        # Mock client for development
  providers/             # (planned) Multi-cloud abstraction
kql/                     # KQL query templates (19 templates)
public/                  # Static frontend

Pipeline

The orchestrator runs a deterministic state machine for each dashboard request:

AUTHENTICATING
  → DISCOVERING_RESOURCES
  → SELECTING_RESOURCE
  → CHECKING_ACCESS
  → READINESS_PROBES
  → SCHEMA_PROFILING
  → MAPPING_BUILD
  → DASHBOARD_BUILD
  → CACHING_RESULTS
  → READY

Each state transition is persisted for debugging. Error states: NO_ACCESS, NO_DATA, PARTIAL_DATA, FAILED.

Multi-Cloud Design

The architecture is designed for multi-cloud from day one. A CloudProvider interface abstracts all cloud-specific operations.

AzureApp Insights + Log Analytics (implemented)
AWSCloudWatch + X-Ray (planned)
GCPCloud Logging + Trace (planned)

Auth Design

Currently, Entra ID OAuth handles both authentication (identity) and data access (Azure token) in a single flow. For multi-cloud, these will be decoupled:

  • Layer 1 (Identity): Supabase Auth / Entra ID / Google — who is the user?
  • Layer 2 (Data Access): Per-cloud OAuth — what can they access?

For Azure users, the experience stays identical (one click). Non-Azure users get a "Connect your cloud" step after login.
